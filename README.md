# Bisaya Post-Class Speech and Affective State Recognition — Group 3

CS412 research mini-project. Group 3 studies **Second-Year Computer Science students** (participant codes
`Y2-041`–`Y2-080`). The research question: does *how* a single Bisaya word is spoken right after class carry
information about the speaker's independently self-reported valence and arousal?

This repository is the **computational research pipeline** (no end-user application). It goes from raw
smartphone recordings and the metadata sheet to cleaned data, standardised audio, acoustic features,
speaker-independent machine learning, evaluation and a validated research report. Every step is one script, every
number in every report is generated from the data, and the whole run is reproducible with one command.

## Results at a glance

<!-- RESULTS:START -->
*Generated by `src/09_build_final_report.py` on 2026-10-04 from the pipeline outputs; full detail in the report.*

- **Data:**
  - 40 metadata participants. By the group's decision the analysis uses the CS2B_v2_wav_16k delivery: 40 trimmed 16 kHz WAV copies covering 40 participants (9 without a verified original, 3 edited or clipped). The original recordings are archived, not analysed.
  - 0 participants have no recording, so the protocol minimum of 40 is **met** (n = 40).
  - One file per participant (the delivery's take for participants recorded more than once).
- **Self-reports:** valence 3–5 for 37 of 40 and arousal 3–5 for 30 of 39. Valence and arousal correlate (ρ = 0.71). Only 3 participants reported unpleasant valence; not modelled (too few per class): valence_5, arousal_5, valence_3.
- **Acoustics vs affect:** after FDR correction, 0 of 108 features are associated with arousal and 0 with valence. 5 files with a different audio configuration (copies of the originals) do not differ significantly in any feature.
- **Speaker-independent ML** (logistic regression, RBF SVM, random forest vs dummy baselines; 10× repeated nested grouped CV):
  - No learned model exceeded the label-permutation null after Holm correction (all adjusted p ≥ 0.05; smallest unadjusted p = 0.0220, before correcting for 9 tests). Before correction, 1 of 9 tests had p < 0.05 (Random forest on arousal_3: p = 0.022). If no model carried any signal, about 0.45 such results would be expected by chance across these tests, and none survives the correction.
  - Best point estimates: valence_2: Random forest balanced accuracy 0.595 [95% CI 0.474, 0.714] (chance 0.50); arousal_2: Random forest balanced accuracy 0.559 [95% CI 0.427, 0.692] (chance 0.50); arousal_3: Random forest balanced accuracy 0.476 [95% CI 0.346, 0.615] (chance 0.33).
  - Pairwise comparisons found SVM (RBF) vs Random forest on arousal_3 (Δ = -0.158, p = 0.049) (corrected t-test, uncorrected for the number of comparisons).
- **Lexical control:**
  - the acoustic features identify *Kapoy* vs other words (balanced accuracy 0.85, permutation p = 0.002);
  - word choice vs the self-reports: valence_2 p = 0.006; arousal_3 p = 0.048;
  - within *Kapoy*, 0 of 12 prosody–affect correlations pass FDR correction.

  So any above-chance score can reflect *which* word was said rather than *how* it was said.

## Run it

**Full step-by-step guide for the team: [docs/RUNNING.md](docs/RUNNING.md)** (Windows, macOS, Linux;
data, options, review tasks, troubleshooting).

Windows (PowerShell), with Python 3.12 and Git installed:

```powershell
git clone https://github.com/everyonehatesralph/AC_miniproject.git
cd AC_miniproject
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run_pipeline.py
```

On macOS/Linux, use `python3.12 -m venv .venv`, then `.venv/bin/python` instead of `.venv\Scripts\python.exe`.

The recordings are not in the repository (participants' personal data).
- **Current setting:** the analysis uses the CS2B_v2 16 kHz WAV copies (`data/audio_source.json`). Put them in
  `data/supplied_audio/CS2B_v2_wav_16k/`; their hashes are checked on every run.
- **Without that file:** step 00 downloads the original recordings from the group's Google Drive folder.

Options:
- `--skip-fetch`: the recordings are already in `data/raw/`.
- `--from 05`: resume from a step (`01b`, `03b`, `09b`, `09c` and `10b` are steps too).
- `--quick`: installation test only. It overwrites the results; see RUNNING.md.

Unit tests (synthetic signals and small tables; no recordings needed). They also run on GitHub for every push
(`.github/workflows/tests.yml`):

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest
```

A full run takes about 1 hour on 16 cores; almost all of it is the random-forest permutation tests. Expected
validation: `PASS 22, BLOCKED 2, WARNING 1, FAIL 0`.

## Privacy

- Participants appear only as pseudonymous codes.
- The raw videos (faces, possible GPS tags) stay in `data/raw/`; only audio is analysed, and no frame or
  location tag is extracted.
- Do not share `data/raw/` or `reports/phase0/media_inventory.csv` outside the research team.
- No audio is in Git: `*.wav`, `*.mov` and `*.mp4` are ignored everywhere, including the listening-review copies in
  `data/review/audio/`. Signed consent forms (names) never go into this repository.
